# HENIX v1.0.0

HENIX gives a network analyst a local workspace for captures up to 5 GiB. This release adds portable investigations, analyst-authored findings and controls over the evidence sent to AI providers.

## Keep and hand off an investigation

- **Case files** saves a `.henix` workspace with the original capture, index, acquisition history, display filter, pins, conclusion and provider review history. Reopening verifies the stored checksums. Compatible cases can reuse the index. A version mismatch or the **Rebuild index** option triggers fresh dissection.
- **TCP conversations** searches across all matching streams by address, port or stream number. Pin its first and last matching frames or pin a packet or finding directly. Capture-wide notes survive filter changes and appear in reports.
- **Report → Pin frame numbers** links up to 32 frames from any conversations in one capture under a shared analyst note. Re-importing identical evidence records each acquisition under the same SHA-256.
- **Report** exports printable HTML or a ZIP with the report, evidence manifest, timeline, filters and an observed-flow diagram when timeline events exist.

## Control AI review

OpenAI, Claude, Gemini, Grok, Groq, DeepSeek and OpenRouter have named presets. Compatible gateways can use a custom URL, API format and key header.

- Inspect the request destination, headers and exact JSON body before submitting up to 40 matching frames. Default redaction replaces endpoint identities, omits names and hides the display filter. The preview masks the API key.
- Set `HENIX_AI_ALLOWED_ORIGINS` on the server to restrict built-in and custom providers by scheme, hostname and port.
- Inspect each observation against its evidence ID and cited frames. Approve individual observations to include them in HTML and ZIP reports. Saved workspaces retain the original provider response and its approval state.

## Capacity and verification

Background indexing streams uploads to disk. SQLite supports packet pagination and filtered views. Bounded caches retain recent frame details and filter results. Long-running indexing, filtering and inspection operations offer cancellation.

The test suite covers real TShark dissection, integrity checks, case restoration, report scope, provider request formats, redaction and citation validation. Browser tests exercise the end-to-end workflow with Chromium and a local provider fixture. A separate capacity harness streams generated captures through the HTTP interface and measures upload and indexing time, late-frame inspection, sampled memory and workspace disk use. The release workflow attaches the benchmark JSON files.

## Run HENIX

Install Python 3.10+ and Wireshark 4.4+ with TShark. Extract the source archive, open a terminal in the project directory and run:

```sh
python app.py
```

The server opens a loopback browser workspace. Download a `.henix` file before closing a case if you need to resume analysis later. A saved case contains readable packet bytes and provider responses. Verify its source and protect it like the original evidence. For third-party cases, rebuilding the index lets the local decoder establish the packet metadata independently.

The 5 GiB limit applies per capture. Throughput depends on packet count, protocol mix, disk and host resources. Captures above 32 MiB use single-pass indexing. Encrypted or truncated frames expose only the data available to the dissector. Live provider access depends on the selected model and account.
